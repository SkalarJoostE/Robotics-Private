What a web version would need

Today an engineer runs these flows in Claude Code on a PC that has the workspace, the VPN, SVN and the log reader. A web page where anyone can ask a question is only a new front door. Behind it, a server still needs the same workspace and the same access, and every answer is paid per conversation through the API.

{{MATRIX}}

Good: reading and reasoning that a web chat can answer. Partial: the answer is fine, a person has to approve what is kept. Engineer PC: changes order software or SVN, needs the robot application, or waits on an engineer at every step, so it stays with an engineer.

Already built

  • A working chat engine (lab-chat-poc), in use since July 2026. It uses the same instructions, skills and log reader as Claude Code, so it gives the same answers.
  • Two channels: lab questions about an order, and RB/ES helpdesk tickets.
  • Read-mostly by design: the helpdesk channel never writes to Jira and ends with a draft reply for a person to send.
  • Cost logging per turn, which is where the figures on this page come from.

Still missing for a shared web page

  • The page itself: a place to type a question and upload a log or zip.
  • One always-on server with the workspace, VPN, SVN and the log reader.
  • API billing: a personal subscription cannot be shared, so a shared service runs on an API key.
  • A queue per order: refreshing an order discards local edits, so two people asking about the same order must not run at once.
  • Tighter permissions and agreement with IT on sending customer logs and software to a cloud model.
  • Review at first: an engineer checks answers before the asker sees them, until case types prove reliable.
